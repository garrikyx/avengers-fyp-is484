# Telemetry System Log Specifications & Universal Standards

## 1. Executive Summary

This specification defines the structural schemas and industry standards for synthetic log files generated by the `simulator` application. The simulator produces continuous log streams mimicking production-grade institutional trading systems. All log formats comply with global financial communication protocols (FIX Protocol) and standard IT infrastructure logging patterns (ISO 8601, Delimited Key-Value Pairs). Raw log payloads are generated strictly for real-time telemetry extraction and must not be persisted permanently.

---

## 2. Telemetry Stream Specifications

### A. Financial Information eXchange Stream (`Fix.log`)

* **Protocol Standard:** FIX Protocol Version 4.2 (Pipe-delimited `Tag=Value` syntax).
* **Sample Record:**
```text
2026-08-26 11:05:16.123 : 8=FIX.4.2|9=140|35=8|49=MAGIC|56=CLIENT|11=ORD1001|55=AAPL|54=1|38=100|44=150.50|10=112|

```


* **Protocol Field Mapping:**
* `8=FIX.4.2`: Protocol version identifier.
* `9=140`: Body length in bytes.
* `35=8`: Execution Report (order status update / trade fill).
* `49=MAGIC` / `56=CLIENT`: Sender and Target CompID headers.
* `11=ORD1001`: Client Order ID (unique order tracking key).
* `55=AAPL` / `54=1` / `38=100` / `44=150.50`: Symbol, Side (`1` = Buy), Order Quantity, and Price.
* `10=112`: Mandatory 3-digit trailing checksum.



### B. Enterprise Infrastructure Stream (`Application.log`)

* **Format Standard:** Standard Enterprise Log Format (Log4j / Logback pattern).
* **Sample Record:**
```text
2026-08-26 11:05:16.123 [INFO] [CoreEngine] Heartbeat active. Connected session count: 12

```


* **Structure Breakdown:**
* **Timestamp:** ISO 8601 standard (`YYYY-MM-DD HH:MM:SS.mmm`).
* **Log Level:** Standard severity rating (`[INFO]`, `[WARN]`, `[ERROR]`).
* **Component:** Emitting sub-module (`[CoreEngine]`).
* **Payload:** Free-form application system event telemetry.



### C. OMS Audit Streams (`Order.log` & `Execution.log`)

* **Format Standard:** Key-Value Pair (KVP) Pipe-Delimited Audit Stream.
* **Sample Record:**
```text
2026-08-26 11:05:16.123 [ORDER_MGMT] NEW_ORDER | ID: ORD1001 | Symbol: AAPL | Side: BUY | Qty: 100 | Price: 150.50

```


* **Structure Breakdown:** Optimized for high-throughput regex and structured parsing engines. Key attributes (`ID`, `Symbol`, `Qty`, `Price`) are explicit to simplify downstream metric aggregation.

## 3. Industry Standards & Real-World Rationale

* **Global Interoperability:** Over 90% of global equities, FX, and derivatives venues exchange order state events using the FIX Protocol. Aligning simulator formats with FIX 4.2 ensures downstream log monitoring agents accurately mirror production environments.
* **Ingestion Efficiency:** Using pipe-delimited key-value tags and standard ISO timestamps ensures zero-friction parsing for log collection tools (Datadog, Splunk, Elastic, Python regex engines).
* **Auditability & Compliance:** Institutional trading platforms require deterministic, millisecond-accurate order audit trails to satisfy regulatory requirements. Explicit order identifiers (`ORD1001`) enable full end-to-end lifecycle reconstruction.
